# 다른 PC에서 빌드·다운로드·플래싱하기 위한 작업 계획

목표는 이 저장소만을 시작점으로 소스 확보, 빌드, 배포 이미지 다운로드와 검증, 기기 식별, 백업, 플래싱 및 복구를 수행하는 것입니다. 현재 그 전체 경로는 **미완성**입니다. 문서나 도구 일부가 있다고 설치 가능한 ROM이 제공되는 것은 아닙니다.

## 현재 사용할 수 있는 검사

Python 3 표준 라이브러리만 필요합니다. 기기 접속, 파일 추출 또는 이미지 수정은 하지 않습니다.

```sh
python3 -m unittest discover -s tests -v
python3 tools/audit_boot.py --device acer-a1-840fhd /path/to/boot.img
```

Windows에서는 `python3` 대신 설치된 `python` 명령을 사용할 수 있습니다.

- 종료 코드 0: 지원하는 boot/ramdisk 범위의 검사만 통과
- 종료 코드 1: 승인키, 키 파일 또는 보안 기본값 문제 발견
- 종료 코드 2: 파일 누락, 지원하지 않는 형식 또는 파싱 실패

이 검사는 gzip/newc ramdisk의 명명된 키 파일, PEM 개인/공개키, Android ADB 공개키 serialization, 명시적 ADB 인증 및 기본 권한 설정을 확인합니다. 키의 내용이나 호스트 식별자를 출력하지 않습니다. 인증서 안의 공개키는 private key와 구분해야 하며, 모든 형식의 숨겨진 키를 찾는 완전한 포렌식 검사가 아닙니다.

`boot_key_audit_passed=true`여도 `publication_approved=false`입니다. system/vendor 파일, 커널 내부, 라이선스, 기기 동작 및 flash 레이아웃은 이 도구가 검증하지 않습니다.

## 아직 남은 필수 작업

1. **소스 재현**: 전체 upstream manifest를 커밋으로 고정하고 기기 트리, 누락된 프로젝트 변경 및 생성 입력을 확인합니다. 커널 빌드 중 임시 적용한 변경도 복원된 현재 소스와 구분합니다.
2. **출처 및 vendor**: 파일별 라이선스 근거를 마련하고 재배포가 불명확한 것은 배포하지 않습니다. 기기 소유자가 원본에서 추출할 수 있는 절차와 기대 해시를 마련합니다.
3. **새 boot**: 특정 PC의 `/adb_keys`, 개인 서명키, 진단용 강제 승인 및 인증 비활성화 없이 패키징합니다. 기존 이미지와 다른 새 파일명·해시를 사용합니다.
4. **안전한 기본값**: 네트워크 ADB는 기본 자동 활성화하지 않고 사용자가 선택하도록 구성합니다. 개발용 root/SELinux/장치 권한의 한계를 명시합니다.
5. **ROM 전체 검사**: sparse/ext4 system까지 검사하고 Google APK 등 포함물의 재배포 조건을 확인합니다. boot 검사만으로 공개 승인하지 않습니다.
6. **클린 빌드**: 기존 PC의 절대 경로와 기존 out 디렉터리에 의존하지 않는 깨끗한 경로에서 빌드합니다. 자료 확보 실패 시 검증을 생략하지 않습니다.
7. **다운로드 및 플래싱**: Release manifest, 체크섬, 모델·파티션 확인, 명시적 실행 승인, 백업과 복구 안내를 제공합니다. 부트로더가 `baylake`라고만 응답하는 것을 A1-840FHD 확인의 충분한 증거로 삼지 않습니다.
8. **최종 확인**: 실제 장치 회귀 결과와 미검증 사항을 분리한 뒤 시험판 Release를 제공합니다.

## 실제 기존 후보 검사 결과 — 2026-10-11

기존 `boot-NATIVE-CHARGING-oct10.img`에는 ramdisk `/adb_keys`가 있습니다. 검사에서 ADB 승인키 파일 및 Android ADB 공개키로 검출했습니다. **이 파일은 공개 배포하지 않습니다.** 개인키가 있다는 의미는 아니지만 개인 PC의 승인 공개키도 이번 배포 범위에서 제외합니다.

기존 커널/부트 포맷 유지 여부와 별개로 새 boot를 실제로 패키징하고 검증해야 합니다. 기존 이미지의 해시를 새 공개용 이미지의 해시로 재사용하지 않습니다.
